What Path-Sensitivity Means

Standard static analysers match vulnerability patterns at the line level without understanding execution context. This causes false positives where a flagged pointer dereference is, in reality, guarded by an if (ptr != NULL) check on a preceding branch.

The V3 engine constructs a full Control Flow Graph (CFG) — a directed graph where each node is a basic block of code and each edge represents a possible execution path. It then simulates data-flow across every path, tracking variable states in real time.

  • Pointer Lifetime Tracking: Each pointer is assigned a state (Unallocated / Allocated / Freed / Dangling) at each CFG node. Use-After-Free and Double-Free are detected by state-machine transitions, not pattern matching.
  • SSA (Static Single-Assignment) Analysis: Variables are renamed at each definition point, making data-flow provenance unambiguous. Uninitialized reads are caught by reaching-definition analysis.
  • Big-O Complexity Inference: Because the global execution graph is available, the engine classifies loop nesting and recursion growth patterns into formal complexity classes.

34-Feature Vector Breakdown

Base 21 Features (shared with DL V1 + Ensemble)
  • LOC, function count, cyclomatic complexity, max nesting depth
  • Memory leak count, unsafe C function count
  • Recursion count, max recursion depth
  • Pointer dereference count, UAF, double-free, invalid-free indicators
  • Uninitialized variable count, null pointer dereference count
  • Out-of-bounds indicator, SSA data-flow issue count
  • Code smell count, conditional count, time complexity score, language encoding
13 Path-Sensitive Features (exclusive to V3)
  • CFG node count & edge count
  • Number of unreachable CFG paths
  • Pointer state transitions per path (safe / unsafe / ambiguous)
  • SSA phi-function count (join points where paths merge)
  • Loop-carried dependency count
  • Path-guarded vs. unguarded dereference ratio
  • Recursive call-graph depth (inter-procedural)
  • Dominance-frontier count (CFG structural complexity)
  • Cross-function pointer alias count
  • Conditional-free unsafe-call count

Training Data

V3 is trained on juliet_data.csv (NSA Juliet C Test Suite) augmented with synthetic CFG-level perturbations to increase path diversity. The Random Forest uses 500 estimators with balanced class weights and a max depth of 25 to capture deep path interactions without overfitting.

Training pipeline: feature extraction via V3 CFG analyser → StandardScaler normalisation → RandomForestClassifier (scikit-learn) → serialised to model_v3_path_sensitive.pkl with its bundled scaler.

When to Use V3

V3 is the most precise model for C code where pointer aliasing, conditional guards, and execution path diversity are the primary sources of risk. It is slower than DL V1 due to CFG construction, but its path-level analysis eliminates most false positives that DL V1 or the Ensemble may flag.

Recommended for: security-critical embedded C firmware, kernel modules, memory-allocator code, and any codebase where manual memory management is the norm.
