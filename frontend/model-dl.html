Network Architecture

DL V1 uses a slim, well-regularised dense architecture that avoids overparameterisation while maintaining strong generalisation:

Input (19) → Dense 256 + BatchNorm + ReLU + Drop 0.35 → Dense 128 + BatchNorm + ReLU + Drop 0.3 → Dense 64 + ReLU → Output 3 (Softmax)

The model uses BatchNormalization after each wide layer to standardise activations and speed up convergence. Dropout at 30–35% prevents overfitting on the 19-feature structured input space. The final Softmax layer outputs per-class probabilities for Clean, Moderate Risk, and High Risk.

Training Data

DL V1 is trained on a combination of real benchmark data and augmented synthetic samples:

  • juliet_data.csv — C vulnerability samples from the NSA Juliet Test Suite covering CWE classes (buffer overflow, use-after-free, format string, etc.).
  • juliet_java_data.csv — Java-adapted Juliet samples.
  • real_data.csv — Hand-labelled real-world C/Java code snippets.
  • Synthetic augmentation — Gaussian-perturbed samples generated around class centroids to balance the Clean / Moderate / High Risk ratio before training.

The combined dataset is passed through a StandardScaler (saved alongside the model) to normalise the 19-feature vector before inference.

Feature Vector (19 Dimensions)

  • Lines of Code (LOC)
  • Number of functions
  • Cyclomatic complexity
  • Max nesting depth
  • Memory leak count
  • Unsafe C function count (gets, strcpy, sprintf, etc.)
  • Recursion count & max recursion depth
  • Pointer dereference count
  • Use-after-free indicator
  • Double-free indicator
  • Invalid free indicator
  • Uninitialized variable count
  • Array out-of-bounds indicator
  • Null pointer dereference count
  • SSA (Static Single Assignment) data-flow issues
  • Code smell count
  • Time complexity score (numeric encoding of O(1)–O(2^N))
  • Number of conditionals (if/switch branches)
  • Language encoding (0 = C, 1 = Java)

Why Use DL V1?

DL V1 is the recommended default model for most use-cases. It is compact enough to run without a GPU, loads in under a second, and consistently achieves over 91% accuracy on held-out validation data. Its confidence scores align well with human-labelled severity, making it ideal for CI/CD pipeline integration.

For edge cases involving deeply recursive or path-dependent code, pair DL V1 with the V3 Path-Sensitive RF model using Compare All mode.
