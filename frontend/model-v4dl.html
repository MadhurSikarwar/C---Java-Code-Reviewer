Network Architecture

The V4 model is a compact fully-connected DNN designed for speed and accuracy over raw parameter count:

Input (36) → Dense 512 + BatchNorm + ReLU + Drop 0.3 → Dense 256 + BatchNorm + ReLU + Drop 0.3 → Dense 128 + ReLU → Output 3 (Softmax)

Batch normalisation after each wide layer stabilises training over the structured synthetic data distribution. Dropout at 30% prevents co-adaptation between units given the 36-dimensional sparse input.

The Deduplication Problem

Standard analysers flag each occurrence of a pattern independently. In large codebases with repeated array-access patterns, this creates hundreds of duplicate warnings masking genuinely unique, high-severity issues.

The V4 model is trained on a feature vector that explicitly encodes occurrence frequency, path similarity scores, and issue-cluster density alongside the base 19-feature static analysis vector. The extra 17 features are:

  • occurrence_count — How many times this exact issue pattern appears.
  • path_cluster_size — Number of issues sharing the same CFG execution path.
  • inter_function_distance — Call-graph depth between source and sink.
  • dominance_score — Whether this issue dominates (must precede) all paths to exit.
  • 13 additional derived path-similarity metrics from the V3 CFG engine.

Training Data & Synthetic Generation

Unlike the V3 model trained on real Juliet benchmark data, V4 uses structured synthetic data generation that mimics realistic code metric distributions for each risk class:

  • Clean code — Features drawn from low-value ranges: LOC 10–80, CC ≤ 3, zero unsafe calls.
  • Moderate Risk — Mid-range values with 1–2 memory issues and moderate complexity.
  • High Risk — High unsafe-call counts, CC > 10, multiple pointer violations, use-after-free patterns.

Each class generates 20,000 samples with Gaussian noise (sigma = 10–20% of range) added to prevent memorisation, resulting in 60,000 total training samples.

When to Use V4

Use V4 when analysing large, repetitive codebases (e.g. auto-generated C structs, loop-heavy embedded code) where duplicate issue flooding is a known problem. V4's dedup-aware features suppress repeated pattern noise and surface only structurally distinct vulnerabilities.

V4 requires running the full V3 CFG pipeline first to generate the 13 path-sensitive features. It is therefore the most computationally intensive single model but produces the cleanest, lowest-noise reports.
